----------------------------------------------------------------------
Overview
----------------------------------------------------------------------

The program manages a shop database using a fixed-size array of Shop
structures (MAX_SHOPS = 100). Data is persisted in the binary file
shops.dat: the first 4 bytes store the record count as std::int32_t,
followed by that many Shop records written as raw bytes.

----------------------------------------------------------------------
Structure: Shop
----------------------------------------------------------------------

struct Shop
{
    char title[64];
    char address[128];
    char phone[32];
};

Trivially copyable — contains only plain char arrays, which allows raw
binary I/O via reinterpret_cast. Total size: 224 bytes (no padding).

----------------------------------------------------------------------
Why std::int32_t for the count header
----------------------------------------------------------------------

The file header uses std::int32_t (from <cstdint>) instead of plain int or
std::size_t. Plain int has a platform-dependent size (the C++ standard only
guarantees at least 16 bits), and std::size_t varies between 4 and 8 bytes
across architectures. std::int32_t is guaranteed to be exactly 32 bits on
all platforms, ensuring the binary file format is consistent.

Both readShops and writeShops use std::int32_t for the count header,
keeping the read and write sides in agreement.

----------------------------------------------------------------------
Input validation (stdin checks)
----------------------------------------------------------------------

The program uses std::cin.getline() for all string input. After each
getline call, std::cin.fail() is checked to detect buffer overflow (user
typed more characters than the buffer can hold). On overflow:

  a. std::cin.clear() resets the stream fail state.
  b. std::cin.ignore(..., '\n') discards the leftover input.
  c. A field-specific error message is printed (e.g. "Input error: title
     too long").
  d. The operation is aborted without saving.

This pattern is used in:
  - addData()       — for title, address, and phone fields.
  - definePhoneByAddress() — for the search address.
  - main()          — for the menu choice (std::cin >> menuItem with
                      fail() check for non-numeric input).

----------------------------------------------------------------------
Functions
----------------------------------------------------------------------

readShops(Shop *shops)
  Opens shops.dat in binary input mode, reads the 4-byte std::int32_t
  count, validates it (non-negative and <= MAX_SHOPS), then reads count
  Shop records into the buffer. Returns the number of shops read, or 0 on
  any error (does not distinguish between an empty file and an I/O error).

writeShops(const Shop *shops, std::size_t count)
  Opens shops.dat in binary output mode (overwriting previous content),
  writes the count as a 4-byte std::int32_t, then writes all count Shop
  records as raw bytes. Returns true on success, false on failure. On
  failure the file may be left partially written — there is no atomic-write
  mechanism.

addData(Shop *shops, std::size_t *count)
  Prompts for title, address, and phone via std::cin.getline() with
  overflow detection on each field. Stores the entry at index *count,
  increments the count, and persists via writeShops(). Rolls back *count if
  the write fails. Rejects when count >= MAX_SHOPS.

viewData(const Shop *shops, std::size_t count)
  Iterates over the array and prints all records with a 1-based index.
  Prints a message if count is 0.

definePhoneByAddress(const Shop *shops, std::size_t count)
  Prompts for an address with overflow detection, then performs a
  case-sensitive linear search using std::strcmp. Prints the phone number
  of the first match, or a "not found" message.

main()
  Declares the shops array, loads data via readShops(), then runs an
  infinite menu loop (1-Add, 2-View, 3-Search, 4-Exit). Non-numeric menu
  input is caught via std::cin.fail() and the stream is cleaned. The loop
  exits on option 4.
